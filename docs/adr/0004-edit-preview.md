# ADR 0004: Edit previews

Status: Accepted, 2026-10-22 (NEW-52). Extends spec §1.5, §6.3 (public API addition; not in the frozen spec). The budget it previews is ADR 0011's; with style segments (ADR 0012) it previews the changed part.

## Decisions
- New op `layoutEdit(page, rects, text, { font?, glyphs? }) -> EditPreview` (wasm `layoutEdit`, `OpName.layoutEdit`, `DocumentHandle.layoutEdit`). It is synchronous, reads the current working copy, commits nothing and never changes the revision, text index or caches.
- It calls the same `plan_edit` function as `applyChanges` (selection, metrics, font ladder, `layout_unbounded`); the commit then does `Laid::fit()`. There is one layout path, so a preview is never a second opinion. Refusals are the commit's: `EDIT_NO_STYLE`, `EDIT_NO_FONT`, `EDIT_UNSUPPORTED_SCRIPT`, `EDIT_ROTATED_TEXT`, `DOCUMENT_GONE`. The one difference is overflow: a commit refuses `EDIT_NO_FIT`, a preview returns `fits: false` with `neededLines` and `maxLines` (equal to the refusal's details) and every line laid out past the budget.
- `EditPreview`: `lines[{text, baseline, x, width}]` (display points, normalized text), `neededLines`, `maxLines`, `fits`, `approximate`, `runs` (as `ChangeResult.layouts`), `fontSize`, `fingerprint`, `docId`, `revision`, `fontRegistryVersion`, and with `glyphs: true` `glyphs[{line, font, gid, start, end, x, width}]`. `start..end` are UTF-16 offsets into the normalized text (NFC, LF), the caret/overlay coordinates. Glyph tops and bottoms are `baseline - 0.8 * fontSize` and `baseline + 0.2 * fontSize`, as in the spec's quads.
- `EditLayout` (`ChangeResult.layouts[]`) gains `fingerprint`, the value a preview with the same inputs returns. It hashes the text, the budget (from the page), the font choice and the registry version. A preview is stale when `revision` or `fontRegistryVersion` differs; the engine keeps no prepared plan, so nothing else can go stale. `isCurrentPreview(preview, doc)` checks the revision.
- No `renderEditPreview`. It would apply the edit on a throwaway writer pass (redaction removal, font embedding, reopen, interpret, rasterize), tens of ms to hundreds of ms per call, against §10.1's one op at a time. The glyph boxes carry the same placements `emit_plan` writes into the export, so HDDN draws the preview with the page's `editorFace` or the registered font at those x/baselines; browser wrapping never decides anything.
- Cost: one page interpretation (`prepare`) plus shaping. Native release 0.18 ms for a 2-line paragraph; browser timing in the smoke test.
