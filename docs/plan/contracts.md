# Foliark implementation contracts and execution policy

## Public API contract to freeze in NEW-3
Proposed semantic surface (exact signatures to be agreed in contract task): openDocument(bytes, options), inspect(), getCapabilities(operation), getPageGeometry(), extractPositionedText(), select()/hitTest(), search(), renderPage(), registerFonts(), prepareParagraph(), prepareParagraphEdit(), applyChangeSet(), prepareExport(mode, policy), export(plan), cancel(), close()/dispose(). Framework-independent ESM + TypeScript types; Rust core reusable. Separate Node/Bun/Deno bindings, ready-made UI, detection and bundled OCR are not first-release obligations.

All operations return structured result/error/capability diagnostics with document ID, generation and revision where relevant. Capability must distinguish supported, unsupported and not-yet-established; never infer export support from successful preview. Geometry, text, change, layout and export schemas belong to foliark-model; runtime message validation remains mandatory even with generated TS types.

## Source and text
Canonical fallible reader must surface failed stream/filter decoding instead of treating it as an empty content stream. Preserve object/generation, operator span, resource owner, nested Form occurrence, drawing order, matrix/clip and generated-origin IDs. Shared resources can have different visible occurrences; redaction must clone survivors or report document-wide semantics explicitly. Unsupported operators cannot disappear while document is called supported.
Store native character codes, font/glyph mapping, Unicode/cluster mapping and positioned quads alongside rendering primitives. JS indices are UTF-16 code units; search normalization maps reversibly to source clusters. CropBox, Rotate, UserUnit, nested transforms and clipping share one invertible coordinate contract. Never approximate partial-word positions by dividing a word rectangle.

## Paragraph editing
Initial edit subset: horizontal left-to-right Latin, including en/lt/lv/et/pl diacritics and combining clusters. Extraction can support more than editing. Paragraph reconstruction must handle per-line source blocks, hard breaks/soft wraps, indent, columns, overprints and style runs. Rust emits one LayoutPlan: cluster/glyph/font IDs, advances, baselines, lines and fingerprint. DOM input/IME edits text only; preview/export use this plan, not independent browser layout.
Fixed surrounding-content wrap budget, fixed font size; overflow, unsupported script/rotation/font or unrepresentable mapping yields explicit refusal. No silent shrink. Font repair/fallback has explicit deterministic provenance and approximation flags. Remove old text semantics and insert planned glyphs; preserve arbitrary backgrounds/nearby graphics rather than paint guessed white rectangles. Later redaction must remove overlapping replacement text and source; stale search/detection/selection/layout invalidate after revision changes. Undo cannot restore protected bytes into an export.

## Redaction and export
Redaction removes complete effective text clusters, affected decoded image/mask pixels and recoverable vector geometry; overlay is presentation only. Filled paths need boolean subtraction with winding rules; strokes need width/dash/cap/join/miter handling and bounded geometry. Nested/shared Form/image occurrences require tested cloning and resource cleanup. If removal cannot be established, native refuses.
Change intent/commit is separate from export eligibility. Plans bind document generation/revision, font registry, layout settings, policy and output mode; stale or swapped plans fail. Support edit-only and sanitize-only exports with zero redactions.
Raster eligibility depends on supported rendering plus tested pixel removal, not native geometry subtraction. Explicit caller consent; report loss of search/accessibility/interactive features and output mode. No silent fallback. Unsupported rendering still refuses.
Fresh writer owns reference allocation, required PDF fields, graph closure and bounded output. pdf-writer's buffering plus WASM/JS transfer copies count toward budget. Never append to original file or retain orphan objects/history. SDK export success means complete byte handoff, not an OS-confirmed save.

## Strict sanitization
Remove applicable metadata, embedded files, actions/scripts, alternate appearances, comments/form values, thumbnails, hidden optional content, off-page/clipped payload, ActualText/Alt/structure/outline secrets and prior revision/orphan data. Retained fonts/images/masks/color resources may themselves contain hidden original payload and require tested rebuilding, subsetting or refusal.
Invisible OCR search text is a separate preservation requirement: map to visible regions and remove protected text while retaining supported unaffected searchable OCR. Never drop all OCR and describe native output as search-preserving. Interactive/accessibility/link/layer preservation is only claimed when safe and tested; otherwise flatten/remove/refuse according to explicit policy and report losses. Signed/encrypted/repaired inputs have preflight policy and diagnostics; no implied signature preservation.

## Runtime and limits
Single-threaded module worker baseline; no required SAB, COOP/COEP, GPU or OffscreenCanvas. Cooperative work slices plus supervisor hard termination for unresponsive WASM calls. Hard reset increments generation, invalidates handles/plans, settles promises and defines lost-ack/commit-boundary behavior. Resource cleanup releases all owned references/caches; JS/WASM disposal is not a claim of physical-memory wiping.
Limit encoded/decoded bytes, expansion ratios, pages, objects, nesting, pixels, fonts, geometry, operation work, cache and output/transfer bytes. Isolate hostile fixtures. Lazy bounded caches, explicit disposal and cancellation are part of API, not optional polish.
Prepared offline means assets deliberately cached first; cold-offline/missing assets return clear errors. No document contents in caches, logs or network requests. Self-host worker/WASM/fonts on ordinary static hosting with documented CSP, subpath and versioned asset behavior.

## Verification and economical agent process
1. Read task + relevant contract + direct predecessor receipts. Inspect callers before change. Do not reload whole attachment/corpus/log history.
2. One task owner; one integration owner for shared DTOs, manifests/lockfiles and acceptance. Independent modules can run in parallel, but avoid multiple agents editing same files.
3. S mechanical/scoped implementation: Codex gpt-6-luna medium. M bounded subsystem: gpt-6.1-sol medium. Hard contract/architecture: Sol high /plan. Focused commercialization research: gpt-5.6-terra medium. Owner decisions: ME/manual. Use project-approved equivalents if a recorded tier is unavailable; do not silently invent providers/models. Claude Code may execute the same bounded contract if deliberately reassigned; do not run duplicate implementations.
4. /goal first line states end state, proof and 5–8 turn bound. Bound limits one attempt; it never authorizes a false completion or waived acceptance. At bound, attach incomplete receipt and exact next step.
5. Establish stable named commands in NEW-9. Small relevant test + fmt/clippy/type/protocol checks; broaden only for changed scope or required cumulative gate. No tests that merely mirror code.
6. Independent output checkers require leaking negative controls; raw-byte grep and implementation's own renderer/extractor cannot certify privacy. Check text, decoded objects, images/masks/Forms and public appearance separately. No skipped case counted as passing; no representative smoke certifies whole scope.
7. Receipts default <=1500 characters: commit/build/input hashes, touched boundary, exact commands/exits and executed case counts, contract output, limitations, next safe step. Keep larger machine reports separately; summarize only decisive fields.
8. Preserve unrelated work, secrets, browser claims/resource admission and existing approval settings. No deployment/public publication in agent implementation tasks. Owner gates receive concrete prepared evidence.

Planning completed when all tasks/artifacts/dependencies exist and validate. Product completed only after these tasks execute and prove their gates.
